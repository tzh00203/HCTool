# 证据分级标准（dyn-verifier 裁决合同）

## 四级保真度（源自 10 个已验证案例的方法论）

| 级 | 名称 | 手段 | 说服力 |
|---|---|---|---|
| L1 | 执行级实证 | Verilator 全模块 vuln-vs-twin 仿真（含 DPI 差分） | 最高——行为级复现 |
| L2 | 数据流实证 | 组合逻辑 micro-tb（表达式级对拍） | 高——逻辑级复现 |
| L3 | 脚本级实证 | Python 常量折叠 / 概率实验（如 ECC 1/128） | 中高——数值级 |
| L4 | 静态结论 | 纯预言机对照，未动态验证 | 兜底——报告必须显著标注 |

## 裁决三值

- `[poc-success]` 成功判据全部满足（exit 1 + verdict/差分输出）
- `[poc-fail]` vuln 与 twin 行为一致 → 候选大概率误报。
  **伪造性检验是流水线的核心价值之一，如实记录，confidence 只降不升**
- `[poc-blocked]` 环境问题（编译失败、依赖缺失），附完整错误与排查尝试

## 冲突规则

- 动态证据 > 静态证据：hunter 的静态分析结论与本轮仿真冲突时，以仿真为准
- 置信度只降不升：静态判 High、动态只支撑 Medium → 报 Medium
- 机制再定性合法：动态验证发现真实机制与候选描述不同（如 aes FORCE_MASKS
  High→Medium 案例），如实写"验证后重定性"，这是加分不是失败

## RESULT.md 必含（可复核性底线）

1. 裁决 + 保真度级别
2. 完整复现命令（bash build.sh 即可，路径无关）
3. 原始输出摘录（CONFIRMED 段 + 关键计数）
4. twin 修复 diff 摘要（改了哪几行、依据哪条预言机）
5. （DPI 型）矩阵结果表：哪格 PASS 哪格 FAIL
