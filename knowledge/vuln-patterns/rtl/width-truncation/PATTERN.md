# 位宽截断

## 根因

比较/赋值/传递中位宽被截断，高位不参与——token 比较只比低 32 位等于
碰撞空间缩小到 2^32。

## 代码特征

- 宽信号参与比较时被显式切片：`a[31:0] == b[31:0]`（两边都 128bit）
- 赋值目标窄于源，无拼接/零扩展
- 函数返回类型窄于输入
- 位宽参数化了但比较写死常数

## 盲检方法

1. 找安全比较点：token 比较、key 比较、地址比较、签名校验
2. 核对操作数两侧声明位宽 vs 参与位宽——任何切片都是候选
3. 参数化宽度的地方 grep 魔法数（`[31:0]` 出现在 TokenWidth 参数旁边就是异常）
4. testplan 常写明完整位宽行为（"all 128 bits must match"）——树内预言机

## GT 实例

- OT-013 lc_ctrl token：128bit unlock token 比较截断到 `[31:0]`，
  2^32 暴破可行。testplan oracle 盲检命中。

## 动态验证

构造两个仅高位不同的 token：vuln 判等（放行），twin 判不等（拒绝）。
micro-tb 级别即可。
